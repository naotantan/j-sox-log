# J-SOX対応 システムログ管理ガイドライン（AWS環境版）

金融商品取引法に基づく内部統制報告制度（J-SOX）への対応として、財務報告に関連するシステムをAWS上に構築・運用する際に、開発ベンダーが設計・実装・引継ぎすべきシステムログ管理の要求事項を、内部統制の要件とAWSサービスとを対応付けてまとめたガイドラインです。

## 収録ファイル

### 1. `J-SOX_システムログ管理ガイドライン_AWS環境版_v1.2.pdf`

開発ベンダー向けの実装・運用要求事項をまとめた本編（全317ページ）。企業名等の固有情報は含みません。

主な構成:

- **0章 はじめに** — 目的・対象読者・適用範囲・責任分担
- **1章 J-SOXとIT統制の基礎** — なぜログが必要かを、IT統制の三層やITGC・監査人の視点から解説
- **2章 ログ管理要求事項（LR-01〜LR-14）** — 対象範囲、記録項目（5W1H）、時刻同期、改ざん防止、保存期間、アクセス制御、暗号化、監視、定期レビュー、変更管理など14項目の要求事項
- **3章 ログ種別と取得対象マトリクス（L-01〜L-14）** — 取得すべきログ種別の一覧と対象システムへの当てはめ
- **4〜5章 AWSサービス対応詳細** — CloudTrail、Config、CloudWatch Logs、S3、KMS、IAM、Systems Manager、RDS/Aurora/DynamoDB（**Amazon RDS for Db2を含む**）、ネットワーク/エッジログ、セキュリティ検知、通知・自動化、分析・抽出、Backup、CI/CD、Organizations、Artifactなど、要求事項に対応するAWSサービスを具体的に解説
- **6章 リファレンスアーキテクチャ** — マルチアカウント/単一アカウント構成、ログフロー、ログアーカイブアカウント設計、監査人アクセス設計
- **7章 保存期間とライフサイクル設計** — 参照法令・基準、推奨保存期間、階層化実装、削除手続
- **8章 改ざん防止と完全性の実装** — 脅威モデル、CloudTrailログファイル整合性検証、S3 Object LockによるWORM化、完全性テスト
- **9章 監視・アラートと定期レビュー運用** — アラートカタログ、レビューカタログ、例外・逸脱の取り扱い
- **10章 職務分掌とログへのアクセス制御** — 役割と権限マトリクス、特権ID管理、アクセス権棚卸
- **11章 開発ベンダーの実装責任と成果物** — フェーズ別実施事項、成果物一覧、テスト観点、受入チェックリスト
- **12章 監査対応** — 証跡の抽出手順と監査人への提出方法
- **13章 導入ロードマップと移行時の留意点** — 段階的導入、オンプレミス/既存AWS環境からの移行、発注者との合意事項チェックリスト
- **付録** — 用語集、参考文献

### 2. `ログ設計書サンプル_会計システム_RDSforDb2_v1.0.pdf`

上記ガイドラインを実際に適用した記載例として作成した、会計システム（データベース: Amazon RDS for Db2）を想定したログ設計書のサンプル（全10ページ）。本編で要求されている記載事項を、具体的なシステム構成に落とし込んだ場合の記述イメージを示しています。

## 位置づけ

- 対象読者: AWS上で財務報告関連システムを開発・運用する開発ベンダーの設計・構築・運用担当者
- 本ガイドラインは技術要求事項を定めるものであり、内部統制の最終的な整備・評価・監査対応は発注者（利用企業）の責任のもとで行われます
