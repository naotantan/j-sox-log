# J-SOX・監査ログ管理の資料集

システムログの管理と監査ログの保存期間について、ガイドラインと法令調査をまとめたリポジトリです。収録しているのは、次の3種類の資料です。

- J-SOX に対応したシステムログ管理のガイドライン（開発ベンダー向けの要求事項）
- 自動車業界向けに、監査ログの保存期間を日米の法令から整理した調査
- 上のガイドラインを基に、日本の主要10業種ごとの法令を反映した業種編（業種別の分冊）

法令調査は、いずれも法的助言ではありません。保存期間の最終的な決定には、法務部門と監査部門（内部統制）の確認が必要です。

## 収録ファイル

### 1. `J-SOX_システムログ管理ガイドライン_AWS環境版_本編_v1.2.pdf`

金融商品取引法に基づく内部統制報告制度（J-SOX）に対応するための、システムログ管理の要求事項をまとめた本編です（全317ページ）。財務報告に関連するシステムを AWS 上に構築・運用するときに、開発ベンダーが設計・実装・引継ぎする事項を、内部統制の要件と AWS のサービスに対応付けています。企業名などの固有の情報は含みません。

主な構成は次のとおりです。

- 0章 はじめに: 目的、対象読者、適用範囲、責任分担
- 1章 J-SOXとIT統制の基礎: ログが必要な理由を、IT統制の三層、ITGC、監査人の視点から説明
- 2章 ログ管理要求事項（LR-01〜LR-14）: 対象範囲、記録項目（5W1H）、時刻同期、改ざん防止、保存期間、アクセス制御、暗号化、監視、定期レビュー、変更管理など14項目の要求事項
- 3章 ログ種別と取得対象マトリクス（L-01〜L-14）: 取得するログ種別の一覧と、対象システムへの当てはめ
- 4〜5章 AWSサービス対応詳細: CloudTrail、Config、CloudWatch Logs、S3、KMS、IAM、Systems Manager、RDS/Aurora/DynamoDB（Amazon RDS for Db2 を含む）、ネットワーク/エッジのログ、セキュリティ検知、通知・自動化、分析・抽出、Backup、CI/CD、Organizations、Artifact など、要求事項に対応する AWS のサービス
- 6章 リファレンスアーキテクチャ: マルチアカウント/単一アカウントの構成、ログの流れ、ログアーカイブアカウントの設計、監査人のアクセスの設計
- 7章 保存期間とライフサイクル設計: 参照する法令・基準、推奨する保存期間、階層化の実装、削除の手続
- 8章 改ざん防止と完全性の実装: 脅威モデル、CloudTrail のログファイルの整合性検証、S3 Object Lock による WORM 化、完全性のテスト
- 9章 監視・アラートと定期レビュー運用: アラートの一覧、レビューの一覧、例外・逸脱の扱い
- 10章 職務分掌とログへのアクセス制御: 役割と権限のマトリクス、特権IDの管理、アクセス権の棚卸
- 11章 開発ベンダーの実装責任と成果物: フェーズ別の実施事項、成果物の一覧、テストの観点、受入のチェックリスト
- 12章 監査対応: 証跡の抽出手順と、監査人への提出方法
- 13章 導入ロードマップと移行時の留意点: 段階的な導入、オンプレミスや既存の AWS 環境からの移行、発注者との合意事項のチェックリスト
- 付録: 用語集、参考文献

### 2. `業種別_システムログ管理ガイドライン/自動車業界_監査ログ保存期間_日米法令調査_基準日20260201.pdf`

自動車業界の企業（完成車メーカー、部品メーカーなど）が AWS 上で開発・運用する、データベースを持つ Web システムを対象に、監査ログの保存期間を日米の法令・国際基準から整理した調査です（全12ページ、基準日 2026-02-01）。ログを運用ログ・監査ログ・部品構成の変更履歴の3区分に分け、区分ごとに推奨する保存期間と根拠を示しています。特定の企業名は記載していません。

主な構成は次のとおりです。

- 1章 結論: ログの3区分と、区分ごとに推奨する保存期間

- 3〜5章 日本・米国の法令・基準と国連規則（UN-R155）: 推奨の根拠となる法令・基準の一覧
- 6章 設計への影響（留意点）
- 7章 推奨に含めなかったもの

## 位置づけ

- ガイドラインの対象読者は、AWS 上で財務報告に関連するシステムを開発・運用する開発ベンダーの、設計・構築・運用の担当者です。
- 業種編の付録G に収録した業種別の法令調査は、日本国内でデータベースを持つ Web システムなどを開発・運用する企業が、監査ログの保存期間を決める場面を対象としています。調査そのものは AWS に限定していません。
- ガイドラインは、技術的な要求事項を定めるものです。内部統制の最終的な整備・評価と監査への対応は、発注者（利用企業）の責任で行います。
- 法令調査は、基準日の時点の条文と公開情報に基づきます。重要な判断の前に、最新の条文を確認してください。
